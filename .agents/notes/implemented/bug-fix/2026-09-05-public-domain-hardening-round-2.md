# Agent Note: public-domain-hardening-round-2

Status: implemented

## Problem

Colophon was about to be served on a public internet domain behind a reverse proxy (invite-only: the admin creates readers, no signup). A first hardening pass had covered the obvious gaps (unauth lookup, CSRF on photo routes, cover-host allowlist, login timing). The sharper threat model surfaced gaps that pass did not examine: redirect-following after the SSRF host check, unbounded egress reads, uvicorn running without proxy headers (which silently breaks per-IP login throttling behind a reverse proxy), a login page that advertises demo credentials to strangers, missing CSP/Referrer-Policy/HSTS, and per-reader pages with no cache directive. The contracts needed to stay fixed over time, not just the one-time fixes.

## Decision

Shipped five coordinator-audited areas, each pinned by a new file under tests/hardening/ (57 tests; suite total 514, ruff clean). app/lookup.py fetch_provider_cover now fetches https only, follows redirects manually re-validating every hop's host against ALLOWED_COVER_HOSTS (relative Locations resolved with urljoin), and refuses bodies past MAX_COVER_BYTES (10 MB). app/main.py's security_headers middleware sends Content-Security-Policy (default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline' for the server-computed spine style attributes; img-src 'self' data:; object-src/base-uri/frame-ancestors 'none'; form-action 'self'), Referrer-Policy strict-origin-when-cross-origin, Permissions-Policy, HSTS only when settings.cookie_secure is on, and defaults every non-static response to private, no-store via setdefault so the photo route's own directive survives. The two inline <script> blocks moved to static/js (login.js pre-paint theme loaded from <head> with DOMContentLoaded deferral; settings.js provider confirm), which is what makes script-src 'self' true rather than aspirational. Dockerfile CMD and the Makefile serve target start uvicorn with --proxy-headers (FORWARDED_ALLOW_IPS, default 127.0.0.1, stays safe for direct installs); docker-compose documents it. app/routers/auth.py gained _demo_hint: the login page's demo credentials appear only while a demo user exists AND uses_default_credentials still holds, wrapped in OperationalError→False so a pre-migration database cannot 500 the one public page. The auth/files/injection audits found the rest already solid (admin gates are server-side, ownership scoping 404s, uploads contain filenames, CSV is CWE-1236-mitigated, FTS input tokenized+quoted+bound) — tests now pin those contracts so regressions fail loudly. README documents the deployment checklist and the previously-undocumented COLOPHON_COOKIE_SECURE/COLOPHON_BACKUP_DIR.
## Alternatives considered

**Solve reverse-proxy blindness only in docs.** Lost: without --proxy-headers in the start commands, request.client.host behind nginx is the proxy, so the per-IP lockout (5 failures/15 min) aggregates every reader onto one key — a permanent site-wide lockout any attacker can hold, not a config footnote. **CSP with 'unsafe-inline' for scripts.** Lost: it would have neutralized most of the header's value; moving ~40 lines of JS to static files was small and makes the policy real. **HSTS unconditionally.** Lost: on a plain-HTTP install it would pin visitors to HTTPS the server cannot serve; sending it only alongside Secure cookies ties the header to the actual cookie posture. **Cookie-tossing defenses for the double-submit CSRF (fresh token on login form).** Already present; noted only. **Rejecting javascript: cover_urls at save time.** Lost: cover_url never reaches a navigational attribute (server-side cache input only), so rejection adds an error path without closing any browser-reachable hole.
## Consequences

Bought: the public-exposure threat model is now enforced by CI (tests/hardening/ pins auth/invite-only invariants, egress bounds, file containment, injection probes, headers and process flags — a regression in any of them breaks make test), and the README tells the owner the four manual steps TLS/proxy/defaults/backups. Cost: script-src 'self' is now a hard constraint — any future inline <script> breaks the page under CSP and must live in static/js (the no-inline-script test enforces this); style attributes remain an allowed inline-style exception, scoped to server-computed integers; the private/no-store default forbids future HTTP caching of rendered pages, so any performance play must go through the static mount; --proxy-headers in the start commands is inert until the operator sets FORWARDED_ALLOW_IPS, so the lockout fix still depends on one documented env var. The staged subagent audits produced no deliverables (repeated empty-turn stalls on the local model) — all five areas were finished centrally, so the audit trail lives in the kanban cards, not in subagent reports.
